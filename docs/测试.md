自建文件网盘 — 核心挑战梳理
 
先一句话概括：
 
网盘不只是“文件上传下载”，本质是分布式存储 + 大文件传输 + 权限 + 版本/回收站 + 防丢 + 安全 + 高可用，很多人一开始只做上传下载，后面一堆坑。
 
下面按优先级给你拆，适合你做私有云 / CloudVault 这类项目参考。
 
一、文件存储层（最容易踩坑）
 
1. 小文件灾难
 
大量图片、文档这类小文件直接存：
 
- 占用大量 inode，文件系统性能暴跌
- 备份、遍历、扫描极慢
- 元数据膨胀
 
常见方案：对象存储、分块合并、打包、  Rados  / MinIO、或者自己实现类似 blob 池，文件只存一次，元数据单独管理。
 
2. 大文件断点续传
 
- 网络中断、切换网络、浏览器关闭之后继续传
- 不能全部重传
- 要做分块上传 + 块校验
- 服务端需要记录：哪些块已经上传，合并时机
 
3. 重复文件（去重）
 
相同文件只保存一份，多用户引用。
 
- 上传前先算哈希（秒传）
- 防止硬链接/引用计数错乱
- 删除文件不能直接删物理块，引用计数减为 0 才真正清理
- 跨用户、跨目录共享场景，引用逻辑很容易出 bug
 
4. 磁盘扩容、多盘、跨机器
 
后期容量不够：
 
- 不能简单直接挂载新盘
- 文件分散到多块硬盘 / 多台服务器
- 均衡、迁移、故障盘下线
- 普通本地文件系统很难横向扩展
 
二、传输与网络
 
1. 上传下载速度 & 带宽控制
 
- 多用户同时跑满带宽
- 要限速、单用户配额
- 大文件不能一次性读入内存，必须流式
- 公网部署还要考虑跨地域、弱网
 
2. 外网访问（非常现实）
 
如果你打算不是只局域网用：
 
- 端口、公网 IP、NAT、反向代理
- 很多家庭宽带没有公网 IP
- 考虑 FRP / 隧道 / 中转服务器，但是中转会吃掉带宽
- TLS、证书、大文件下  nginx  超时、buffer 配置
 
3. 并发
 
多人同时上传下载：
 
- 连接数控制
- 内存不能被大量文件句柄打满
- 内核  ulimit  调优
 
三、元数据管理（网盘真正的核心）
 
你存的不只是文件，还有一大堆元数据：文件名、路径、所属用户、目录树、大小、修改时间、权限、共享、版本、回收站。
 
1. 目录树
 
- 文件夹增删改查、移动、重命名
- 移动整个目录不能遍历复制所有物理文件，只改元数据
- 不能出现循环、路径冲突
 
2. 数据库压力
 
所有目录、文件、权限都在数据库：
 
- 大量文件列表查询
- 文件夹刷新、分页
- 不要每次打开目录都扫描磁盘
 
3. 事务
 
移动、删除、恢复、共享：
 
- 操作中途崩溃，很容易出现：数据库和实际存储不一致
- 元数据成功，但是磁盘写入失败，孤儿块 / 幽灵文件
 
四、权限、共享、协作
 
1. 用户隔离
 
用户之间文件默认不能互相访问，一旦越权就是严重漏洞。
 
2. 目录 / 文件粒度权限
 
只读、可写、预览、能不能下载、能不能分享。
 
3. 公开分享链接
 
- 生成分享链接、访问密码、过期时间
- 防止遍历、越权访问别人分享文件
- 分享文件被删除之后链接立刻失效
 
4. 多人协作
 
多人同时编辑同一个文件（这个难度直接上升一个档次）
 
- 简单网盘一般只做“文件版本”，不做实时协同
 
五、备份、容错、数据丢失风险（用户最在意）
 
1. 误删除：回收站
 
删除文件不能立刻删掉，只是标记。
 
2. 文件版本历史
 
修改覆盖之后，可以回退历史版本。
 
3. 磁盘损坏
 
单盘挂掉数据直接没。
 
- 多副本
- 纠删码
- 定期快照 / 备份到另一台机器
 
4. 数据校验
 
磁盘静默损坏（bit rot）
 
- 定期扫描文件哈希校验
- 发现损坏自动从副本恢复
 
六、预览、缩略图、媒体
 
- 图片缩略图生成（大量图片很耗 CPU）
- 视频预览、转码（很重，很多网盘直接不做）
- PDF、Office 在线预览
- 缩略图缓存，不能每次打开目录重新生成
 
七、配额、统计、计费（私有网盘也需要）
 
- 每个用户容量上限
- 实时计算已占用空间（如果做了文件去重，这里很容易算错）
- 统计、告警，磁盘满了拒绝继续上传
 
八、安全
 
1. 路径穿越漏洞（最经典， ../  访问别人文件）
2. 恶意文件上传，木马、脚本
3. 越权访问
4. 大文件上传打满磁盘（拒绝服务）
5. 上传病毒文件，如果你对外提供服务风险更高
6. 传输加密（HTTPS）
7. 可选：文件端到端加密（E2EE），这个难度巨大
- 服务器看不到明文
- 缩略图、在线预览基本废掉
 
九、运维
 
1. 磁盘满了怎么告警
2. 磁盘坏了怎么替换
3. 清理孤儿块（引用已经没有，但是物理文件还占空间）
4. 数据库备份
5. 服务重启、升级，不能损坏正在上传的文件
 
 检查一下哪些没有实现
