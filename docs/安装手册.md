# 云匣 CloudVault 安装手册

版本 v0.5.0 · 服务端 CMake C++17 · 客户端 Qt 6 QML

---

## 1. 组件与平台要求

| 组件 | 技术栈 | 可运行平台 | 说明 |
|---|---|---|---|
| **服务端** `server/` | C++17 + POSIX socket + SQLite3（零第三方依赖） | **仅 Linux**（`net/` 用 POSIX socket，Windows 不可编译） | 提供全部 REST 接口 |
| **正式客户端** `src/` + `qml/` | Qt 6 + QML + qmake | **Windows**（MinGW 构建，Linux 亦可自行编译） | 日常使用的图形界面 |
| 测试客户端 `client/` | Qt 6 Widgets + CMake | Windows / Linux | 按钮式接口验证工具，非日常使用 |

依赖清单：

- 服务端：`build-essential`（g++ ≥ 支持 C++17）、`cmake ≥ 3.16`、`libsqlite3-dev`、`libssl-dev`（**可选**，TLS 与静态加密需要）
- 客户端：Qt 6.9.x `mingw_64` 套件 + 匹配的 MinGW（`Qt/Tools/mingw1310_64`）

## 2. 服务端安装（Linux）

### 2.1 一键版

```bash
sudo apt install -y build-essential cmake libsqlite3-dev libssl-dev   # Debian/Ubuntu
# RHEL 系：sudo yum install -y gcc-c++ cmake sqlite-devel openssl-devel

cd server
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)
ctest --test-dir build --output-on-failure     # 期望：自检全部通过
sudo cmake --install build                     # 装到 /usr/local/bin/cloudvault-server
```

### 2.2 构建选项

| 选项 | 默认 | 说明 |
|---|---|---|
| `CMAKE_BUILD_TYPE` | `Release` | `Release` / `Debug` / `RelWithDebInfo` |
| `CV_BUILD_TESTS` | `ON` | 是否构建 `cv_tests` 并注册 CTest |
| `CV_ENABLE_TLS` | `ON` | 找不到 OpenSSL 会自动降级为纯 HTTP（打 WARN） |
| `CV_ENABLE_ASAN` / `CV_ENABLE_TSAN` | `OFF` | Sanitizer，**两者互斥**；配 `Debug` 使用 |
| `CV_INSTALL_TESTDATA` | `OFF` | 是否把 `testdata/` 安装到 `<prefix>/share/cloudvault` |
| `CMAKE_INSTALL_PREFIX` | `/usr/local` | 免 sudo 安装可改成 `$HOME/.local` |

产物：`build/cloudvault-server`、`build/cv_tests`、`build/compile_commands.json`（默认导出，供 clangd）。

### 2.3 首次启动

```bash
mkdir -p /var/lib/cloudvault
./build/cloudvault-server --data-dir=/var/lib/cloudvault --port=8080 --workers=4
```

数据目录自动创建：

```
<data-dir>/
├── meta/cloudvault.db   元数据（SQLite WAL）
├── meta/users.db        账号与会话（独立库）
├── blobs/xx/<hash>      内容寻址分块（去重）
├── files/               文件树物理镜像（按用户：files/u<id>/）
└── tmp/uploads/<id>/    分块上传临时区
```

验证：

```bash
curl -s http://127.0.0.1:8080/healthz
# {"status":"ok","version":"0.5.0","disk_free_bytes":...,"tls_port":0}
bash server/testdata/smoke.sh            # 冒烟：上传→秒传→中文名→下载回读 diff
bash server/testdata/smoke_chunked.sh    # 分块 / 断点续传 / Range
bash server/testdata/smoke_dirs.sh       # 目录树 / 按路径下载
```

### 2.4 必配：鉴权与 HTTPS

**不配 `--auth-token` 时任何人可读写全部文件。** 生产必须配置：

```bash
# 生成自签名证书（含 SAN，10 年有效）
bash server/testdata/gen_cert.sh cloudvault 192.168.1.50
#  → testdata/tls_cert.pem / tls_key.pem（密钥权限自动设为 600）

# 生成静态加密密钥（可选，启用后 blob 落盘 AES-256-GCM 加密）
openssl rand -hex 32 > /etc/cloudvault/data.key && chmod 600 /etc/cloudvault/data.key
```

```bash
./build/cloudvault-server \
  --data-dir=/var/lib/cloudvault \
  --http=off \                       # 关闭明文 HTTP，仅留 HTTPS
  --tls-port=8443 \
  --tls-cert=server/testdata/tls_cert.pem \
  --tls-key=server/testdata/tls_key.pem \
  --auth-token='换成你自己的强口令' \
  --log-file=/var/log/cloudvault.log --log-level=info
```

> `--http=off` 必须同时配 TLS，否则服务端直接报错退出（杜绝"零监听"）。

配置文件方式（等价）：

```ini
# /etc/cloudvault.conf
data_dir=/var/lib/cloudvault
port=8080
http=off
tls_port=8443
tls_cert=/etc/cloudvault/tls_cert.pem
tls_key=/etc/cloudvault/tls_key.pem
auth_token=你的口令
log_file=/var/log/cloudvault.log
log_level=info
```

```bash
./build/cloudvault-server --config=/etc/cloudvault.conf
```

### 2.5 全部运行参数

三种配置通道等价，**优先级 命令行 > 环境变量 `CV_*` > 配置文件 > 默认值**。

| 命令行 | 环境变量 | 配置键 | 默认 | 说明 |
|---|---|---|---|---|
| `--data-dir` | `CV_DATA_DIR` | `data_dir` | `/var/lib/cloudvault` | 数据根目录 |
| `--files-root` | `CV_FILES_ROOT` | `files_root` | `<data-dir>/files` | 文件树允许根（显式配，不随 cwd 变） |
| `--listen` | `CV_LISTEN` | `listen` | `0.0.0.0` | 监听地址 |
| `--port` | `CV_PORT` | `port` | `8080` | HTTP 端口 |
| `--workers` | `CV_WORKERS` | `workers` | `4` | 工作线程数 |
| `--chunk-size` | `CV_CHUNK_SIZE` | `chunk_size` | `5242880` | 分块大小 |
| `--log-file` | `CV_LOG_FILE` | `log_file` | 空（stdout） | 日志路径 |
| `--log-level` | `CV_LOG_LEVEL` | `log_level` | `info` | debug/info/warn/error |
| `--auth-token` | `CV_AUTH_TOKEN` | `auth_token` | 空（不启用） | Bearer 令牌 |
| `--http` | `CV_HTTP` | `http` | `on` | 明文 HTTP 开关 |
| `--tls-port` | `CV_TLS_PORT` | `tls_port` | `0`（关） | HTTPS 端口 |
| `--tls-cert` / `--tls-key` | `CV_TLS_CERT` / `CV_TLS_KEY` | `tls_cert` / `tls_key` | 空 | PEM 证书 / 私钥 |
| `--data-key` | `CV_DATA_KEY` | `data_key` | 空（不加密） | 静态加密密钥文件（64 hex 或 32 字节原文） |

`CV_CONFIG` 环境变量或 `--config=<file>` 指定配置文件。

### 2.6 systemd 托管（可选）

```ini
# /etc/systemd/system/cloudvault.service
[Unit]
Description=CloudVault Server
After=network.target

[Service]
ExecStart=/usr/local/bin/cloudvault-server --config=/etc/cloudvault.conf
Restart=on-failure
User=cloudvault

[Install]
WantedBy=multi-user.target
```

```bash
sudo useradd -r -s /usr/sbin/nologin cloudvault
sudo chown -R cloudvault /var/lib/cloudvault
sudo systemctl daemon-reload && sudo systemctl enable --now cloudvault
sudo journalctl -u cloudvault -f
```

## 3. 客户端安装（Windows）

### 3.1 编译

任选其一：

```powershell
# PowerShell（推荐）
.\scripts\build_windows.ps1
# 指定路径：-Qt D:\Qt\6.9.3\mingw_64 -MinGW D:\Qt\Tools\mingw1310_64
# 全量重编：-Clean
```

```bat
:: cmd
scripts\build_windows.bat
```

```bash
# 手动（等价）
mkdir build_official && cd build_official
qmake.exe ../File.pro
mingw32-make -j4 SHELL=cmd.exe
```

> 路径写死在脚本里，按需改：Qt=`D:\Qt\6.9.3\mingw_64`，MinGW=`D:\Qt\Tools\mingw1310_64`。
> `SHELL=cmd.exe` 不能省：qrc 变化时 Makefile 是反斜杠路径，走 `/usr/bin/sh` 会 Error 127。

产物：`bin/CloudVault.exe`

### 3.2 部署 Qt 运行时

`bin/` 已在 `.gitignore` 中（约 100 MB），克隆后需重新执行：

```bash
bash scripts/deploy_windows.sh
bash scripts/deploy_windows.sh <Qt前缀> <MinGW前缀>
```

脚本做四件事（幂等）：`windeployqt --qmldir qml` 收集 Qt DLL + QML 模块 → 补齐 `bin/tls/` 三个 TLS 后端插件 → 补齐 MinGW 运行库 → `objdump` 校验全部直接依赖。

验证自包含：

```bash
CLEAN=$(echo "$PATH" | tr ':' '\n' | grep -iv "qt\|mingw" | paste -sd: -)
env PATH="$CLEAN" QT_QPA_PLATFORM=offscreen timeout 5 ./bin/CloudVault.exe   # 期望 exit=124（超时仍在运行）
```

完成后 `bin/` 可整目录拷到其他 Windows 机器，**无需安装 Qt**。

### 3.3 Linux 编译客户端

```bash
qmake File.pro && make -j$(nproc)
```
Qt 模块需求已在 `config.pri` 声明：`core gui qml quick quickcontrols2 network sql concurrent`。

## 4. 首次连接

1. 双击 `CloudVault.exe` → 左侧「设置」
2. 协议选 `https`（或测试用 `http`），主机填服务器 IP，端口填 `8443`（HTTP 则 `8080`）
3. 访问令牌填服务端 `--auth-token` 的同一个值
4. 点【保存设置】→【测试连接】
5. **HTTPS 自签名首次连接**会弹证书确认框：核对弹出 SHA-256 指纹与服务端 `gen_cert.sh` 输出的指纹一致后点【信任】（TOFU，指纹写入本机 `settings.ini`）

> 令牌栏在已登录状态下由会话托管，无需手填。

## 5. 排障速查

| 现象 | 原因 / 处理 |
|---|---|
| 连不上、`连不上服务器` | 服务端未启动 / 端口不通 / `--http=off` 后仍用 http 协议访问 |
| `401 令牌无效` | 令牌与 `--auth-token` 不一致；设置页重新填写或直接登录 |
| 弹「证书已变更」对话框 | 本机固定指纹与新证书不符：换证书→点【清除记录并重新信任】；未换过→高度警惕中间人攻击 |
| 上传报 `507` | 服务端磁盘不足（判定 = 文件大小 + 64 MiB 余量） |
| 上传大文件被拒 `413` | 单次 > 64 MiB，客户端会自动改走分块上传；若仍失败检查 `--chunk-size` |
| `找不到 TOR 依赖 DLL` | 未跑 `scripts/deploy_windows.sh` |
| 界面「白字白底」 | 未使用 `build_official` 产物或改动了 `src/app/main.cpp` 的配色钉死逻辑 |
| 服务端报 `建表失败: no such column: owner_id` | 老版本二进制，升级到 v0.5.0+（迁移顺序已修） |

日志文件：`<LocalAppData>/CloudVault/logs/cloudvault.log`

## 6. 卸载 / 备份

- **备份**：服务端整拷 `<data-dir>`（`cloudvault.db` + `users.db` + `blobs/`）；客户端备份 `settings.ini`
- **卸载**：删 `bin/` 目录 + `stop/disable` systemd 服务 + 删除 `<data-dir>`（**不可恢复**）
