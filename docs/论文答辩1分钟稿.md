## 1. 逐字稿（连读，258 字 / 53~62 秒）

> **Why** —— 各位老师好。市面上的网盘要么方便但数据在别人手里，要么数据自持但部署太重。我想做一个**部署轻、数据 100% 自有**的私有云盘。
>
> **What** —— 我做的是**云匣 CloudVault**，客户端加服务端。服务端 1.35 万行 C++17，**零第三方依赖**，自研 HTTP 服务器加 SQLite3，51 个接口；客户端 2.66 万行 Qt6 加 QML，功能覆盖账号、文件、传输、版本、标签、分享、回收站、同步**八个模块**。
>
> **How** —— 三个关键设计：**内容寻址分块存储**，去重加秒传；**双向同步绝不静默丢数据**；**双库加归属隔离**，越权一律 404。**168 条断言全部通过。**

## 2. 三段拆解版（想临场组织语言时看这个）

### Why —— 为什么做（0:00–0:20）

| 痛点 | 现有方案的硬伤 | 我的回答 |
|---|---|---|
| 数据不在自己手里 | 公有云限速、订阅、数据在第三方服务器 | 数据 100% 落在自己的硬盘 |
| 部署太重 | Nextcloud 需 PHP + 多组件 | 服务端零第三方依赖，单二进制 |
| 硬件门槛高 | NAS 2000 元起 + 学习成本 | 一台闲置 PC / 迷你主机即可 |
| 误删误覆盖无处可寻 | 微信传文件、U 盘、邮箱 | 回收站三态 + 版本快照 |

**一句话定位**：部署在自己设备上的轻量私有云盘 —— 数据自己存、同步自动做、分享可控、找文件快。

### What —— 做了什么（0:20–0:35）

- **服务端**：C++17 / Linux / POSIX socket + SQLite3，**零第三方库**，5 层单向依赖（core→meta→store→net→app），**51 个 REST 接口**。
- **客户端**：Qt 6 / C++17 + QML，7 层单向依赖（core→net→sync/transfer→data→controllers→app），9 页面 + 11 控件 + 10 对话框。
- **数据层**：两库分离 —— `users.db`（账号会话）+ `cloudvault.db`（文件业务），共 18 个持久化实体。
- **功能**：M1 账号会话、M2 文件目录、M3 分块上传、M4 版本历史、M5 标签、M6 分享链接、M7 恶意文件判定、M8 客户端本地持久化。
- **规模**：服务端 1.35 万行 + 客户端 2.66 万行 ≈ **4 万行**。

### How —— 怎么做的（0:35–1:00）

| 亮点 | 做法 | 带来什么 |
|---|---|---|
| **内容寻址分块** | 文件按固定块切分，以 SHA-256 为键落盘，chunk 表带引用计数 | 去重、**秒传**（分块齐备直接标记完成）、按块回收 |
| **同步不丢数据** | 云端删除只进回收站；本地删除先搬 `sync-trash` 暂存，失败即回退报错；冲突保留两份 | 三条硬规则杜绝静默丢数据 |
| **双库 + 归属隔离** | `users.db` / `cloudvault.db` 分离；登录后强制 `owner_id` 过滤 | 越权一律 **404**（不泄露资源是否存在） |
| **工程纪律** | 密码学用**公开标准向量**验证、并发 8×20 线程压测、构建注册检查 | **168 条断言全部通过** |

## 3. 追问时的深挖点（1 分钟稿讲不到、被问才说）

- **"为什么不用物理外键？"** → 双库架构下 SQLite 跨库无法建约束；回收站软删除依赖会阻碍物理删除并打乱级联顺序。一致性靠"单事务 + 代码显式级联"。
- **"秒传安全吗？"** → 秒传只复用已存在的分块、不新建内容，且带归属校验；判定"已存在"时**同时校验尺寸正确**，避免断电留下的截断 blob 被误判为已存在、导致坏内容永久固化。
- **"怎么防越权？"** → `authUserId >= 1` 时所有查询强制带 `owner_id` 过滤，越权 404；凭证落哈希不落明文；改密按版本号批量失效会话。
- **"同步冲突怎么判？"** → 决策抽在 `SyncPlan` 纯函数里（只回答"该干什么"），执行由 `SyncEngine` 负责；冲突保留两份不覆盖。
- **"最大的不足？"** → 端到端测试缺口（服务端 POSIX socket，Windows 编不了）；客户端上传下载仍是同步阻塞调用，大文件期间界面会卡顿 —— 这条在 `src/sync/SyncEngine.h` 头注释里已标注。
