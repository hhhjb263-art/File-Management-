## 一、什么是验收标准（AC）

**验收标准**是描述一个用户故事所涵盖的**用户/业务需求细节的清单**，它确保该特性或用户故事的**各种应用场景都被考虑到**，团队可完整实现用户需求。

一句话区分：

- **用户故事**回答"谁、要什么、为什么"（需求意图）
- **验收标准**回答"做到什么程度算做完"（完成边界）

### 验收标准的四个好处

| 好处 | 说明 |
|---|---|
| 确定边界 | 明确实现哪些、不实现哪些，防止范围膨胀 |
| 达成共识 | 产品/开发/测试对同一句话理解一致，消除歧义 |
| 测试依据 | 每条 AC 直接对应测试用例与验收清单 |
| 估算基础 | 场景与规则越清晰，工作量评估与排期越准确 |

### 两种编写方法

1. **按场景（推荐）**：`Given（前提）/ When（操作）/ Then（结果）` 描述每个场景，适合交互与流程。
2. **按规则**：列举需求涉及的业务规则、输入输出规则、异常处理规则、安全规则，适合约束与计算逻辑。

### 编写要点（自查清单）

- [ ] 覆盖**非功能需求**（性能、容量、安全、兼容性、易用性）
- [ ] 描述**可执行的操作**和**可见的信息**（不写"系统应优化性能"这类不可验证的话）
- [ ] 写清**输入/输出的内容与格式**（字段名、格式、上限、错误码）
- [ ] 同时覆盖**正常场景与异常场景**（断网、冲突、超限、越权）
- [ ] 每条都有**唯一可判定的通过/不通过**结论
- [ ] 标注**优先级**，便于裁剪与分批交付

## 二、被验收的用户故事

> **作为** 拥有多台设备的个人用户「小陈」，
> **我希望** 把本地"工作文档"文件夹与云端目录建立自动双向同步，
> **以便** 在任意一台设备上打开的永远是最新文件，且任何误操作都不会造成数据丢失。

**优先级定义**

| 级别 | 含义 | 交付要求 |
|---|---|---|
| **P0** | 故事不成立/不可发布的硬门槛 | 全部通过才允许发布 |
| **P1** | V1.0 正式版必须，MVP 可后置 | 进入正式版验收清单 |
| **P2** | 可选增强，可延后到 V1.1+ | 不影响发布 |

## 三、15 条验收标准（含优先级）

| # | 类型 | 验收标准（Given / When / Then） | 优先级 | 关联 FR |
|---|---|---|---|---|
| AC-01 | 场景-正常 | **Given** 客户端已登录且云端目录为空，**When** 建立本地目录↔云端目录的双向同步对，**Then** 本地全部文件按目录结构上传，两端文件数、相对路径、SHA-256 完全一致，状态角标显示"✓ 已同步" | P0 | FR-3-1 |
| AC-02 | 场景-正常 | **Given** 同步对运行中，**When** 本地新增/修改/重命名/删除文件，**Then** 事件经 5 秒防抖合并后自动入队上传，云端在 30 秒内呈现相同变更；重命名按 rename 事件同步，不产生删除+重传 | P0 | FR-3-1 |
| AC-03 | 场景-正常 | **Given** A、B 两台设备同步同一云端目录，**When** A 端修改并提交成功，**Then** B 端在 **10 秒**内收到变更并落地同一内容，双方最终一致 | P0 | FR-3-1 |
| AC-04 | 规则-版本 | **Given** 文件每次被修改且同步成功，**When** 生成新版本，**Then** 旧内容进入版本库（默认 ≤10 个版本且 ≤90 天），时间线可查版本时间/大小/来源设备；**纯重命名不产生新版本** | P0 | FR-4-1/4-2/4-3 |
| AC-05 | 规则-删除 | **Given** 任一删除动作（本地删除、Web 删除、同步删除），**When** 执行删除，**Then** 对象先进回收站保留 **30 天**并可原位置还原；**且** 从未出现"一端删除导致另一端数据不可恢复"的情况 | P0 | FR-3-6 / FR-8-1 |
| AC-06 | 规则-忽略 | **Given** 同步目录含 `Thumbs.db`、`.DS_Store`、`*.tmp`、`~$*` 及 `.cvignore` 中声明的路径，**When** 触发同步，**Then** 上述文件**不上传、不下载、不产生冲突**，且同步日志中标记为"已忽略" | P0 | FR-3-4 |
| AC-07 | 场景-异常（冲突） | **Given** A、B 双端离线各自修改同一文件，**When** 双方恢复联网，**Then** 较新者为主文件，较旧者另存为 `文件名(冲突-设备名-时间).ext`，**两份内容均存在，零数据丢失**，并在冲突清单中可定位 | P0 | FR-3-5 |
| AC-08 | 场景-异常（改删冲突） | **Given** A 端修改文件、B 端删除同一文件，**When** 双端同步，**Then** 按"修改优先"处理：被删端恢复该文件并向用户提示，不以删除覆盖修改 | P0 | FR-3-5 |
| AC-09 | 场景-异常（中断） | **Given** 正在上传 10GB 文件，**When** 中途拔网线/杀进程/服务重启，**Then** 恢复后从已完成分块继续，**不重传已完成分块**，最终整文件 SHA-256 与源文件一致 | P0 | FR-2-3 |
| AC-10 | 规则-秒传去重 | **Given** 服务端已存在相同 SHA-256 内容，**When** 再次上传同名或异名文件，**Then** 命中秒传：< 1 秒完成、网络传输字节数 ≈ 0，文件内容引用计数 +1 | P1 | FR-2-4 |
| AC-11 | 场景-批量 | **Given** 一次性复制 1000 个文件（含多级子目录）进入同步目录，**When** 5 秒防抖后入队，**Then** 全部最终同步成功（成功率 100%），传输队列正确显示进度/速度，支持暂停、恢复、取消，失败任务自动重试 3 次 | P0 | FR-2-6 / FR-3-1 |
| AC-12 | 规则-方向配置 | **Given** 同步对配置为"仅上传"或"仅下载"，**When** 对端发生变更，**Then** 变更**不会**反向流动；方向变更后 10 分钟内完成一次全量对账并修正状态 | P0 | FR-3-2 |
| AC-13 | 规则-状态可见 | **Given** 任意同步状态，**When** 用户查看资源管理器与托盘，**Then** 角标准确显示 ✓ 已同步 / ⟳ 同步中 / ⚠ 冲突或错误；点击查看可列出"上传/下载/跳过/冲突"清单 | P0 | FR-3-8 / FR-3-9 |
| AC-14 | 非功能-性能与容量 | **Given** 千兆局域网、100 并发连接、10 万文件量级，**When** 执行同步与检索，**Then** 吞吐 **≥ 80 MB/s**、API P95 **< 300 ms**、名称检索响应 **≤ 500 ms**，且无内存泄漏或服务崩溃 | P1 | 第 6 章非功能需求 |
| AC-15 | 非功能-安全与异常 | **Given** 会话失效、设备被踢下线、连续 5 次密码错误、提取码连错 5 次，**When** 触发对应事件，**Then** 该设备 **30 秒**内停止一切传输、账号锁定 **10 分钟**；**且** 全链路 HTTPS、越权访问与路径穿越尝试均被拒绝并记录审计日志 | P0 | FR-10-2/10-3/10-4 |

## 四、覆盖度自检

| 维度 | 覆盖的 AC | 结论 |
|---|---|---|
| 正常/主流程 | AC-01、AC-02、AC-03 | ✅ |
| 异常/失败 | AC-07、AC-08、AC-09 | ✅ |
| 边界与规则 | AC-04、AC-05、AC-06、AC-10、AC-12 | ✅ |
| 状态与可观测 | AC-11、AC-13 | ✅ |
| 非功能（性能/容量/安全） | AC-14、AC-15 | ✅ |

## 五、常见编写错误（避坑）

| ❌ 错误写法 | ✅ 正确写法 |
|---|---|
| "系统应快速完成同步" | "两台设备间变更在 10 秒内可见" |
| "用户体验良好" | "状态角标准确显示 ✓/⟳/⚠ 三种状态" |
| "支持大文件" | "单文件 ≤100GB，按 5MB 分块，中断可续传且哈希一致" |
| "冲突时妥善处理" | "保留较新者为主文件，较旧者另存为 `文件名(冲突-设备名-时间).ext`" |
| 只写正常流程 | 正常 + 异常 + 边界 + 非功能 四类齐全 |
