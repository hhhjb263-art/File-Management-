# 云匣 CloudVault 客户端 UI 优化方案

> 目标：**功能不变**（服务端契约与全部能力保留），把当前"测试客户端"式界面改造为风格统一、简洁现代、交互清晰、可响应式适配的正式客户端界面。
> 依据：对 `client/src/` 现状的逐行核实（下文每条问题均附 file:line 证据）。

## 1. 待改进的页面 / 组件清单

### G1 · 顶部连接栏（`MainWindow.cpp:196-238`）
**问题**：① 8 个按钮同权重平铺，主操作（上传/下载）与开发动作（健康检查、清空日志、取消上传）混在一起；② 按钮文案过长（"选择文件并上传（可多选）"14 字、"分块上传（断点续传）"），一行宽度必然溢出；③ 地址/令牌属"一次性配置"，却常驻最显眼位置；④ 所有控件 `min-width` 累加已 > 1000px，窄屏直接截断。
**影响**：小屏/笔记本 1366×768 下按钮被压缩或截断，主次不分导致误操作。

### G2 · 状态行（`MainWindow.cpp:241-268`）
**问题**：进度标签、进度条、自签证书复选框、【证书…】按钮、结果标识、服务器空间 6 件挤一行，信息密度过高且性质混杂（进度=瞬时状态，证书=安全配置，空间=环境信息）。
**影响**：进度条被挤压到 min 200px；结果标识只是一个无样式标签，反馈不醒目。

### G3 · 文件列表（`MainWindow.cpp:279-292`）
**问题**：① 暴露内部字段 **ID、Hash 前 8 位、是否秒传**——这是调试信息，普通用户无意义（且"是否秒传"仅本地上传过的文件才有值，`MainWindow.cpp:1013` 注释已承认）；② 列宽硬编码合计 710px，窗口变窄即出横向滚动条；③ 无排序指示器（排序能力靠自绘逻辑）；④ 空列表时是一片空白，无引导。
**影响**：信息密度与可读性双输；窄窗口体验差；新用户不知从何下手。

### G4 · 预览面板（`MainWindow.cpp:314-370`）
**问题**：① 固定 300px + 3:1 比例，未随窗口变化；② 无"折叠/关闭"能力，窄屏时挤压主列表；③ 超过 16 MiB 才提示，但提示按钮"仍要预览（可能很慢）"样式与普通按钮同级；④ 空状态仅显示"（未选中文件）"。
**影响**：笔记本屏幕下主列表可用宽度不足。

### G5 · 日志面板（`MainWindow.cpp:162`）
**问题**：调试日志常驻底部，占 1/3 高度；正常使用时用户几乎不需要它。
**影响**：主内容区被压缩，观感偏"开发工具"而非产品。

### G6 · 状态设计缺失
无**空态 / 加载态 / 错误态**的三态设计：列表空、请求中、请求失败时的界面表现都是"空白 + 日志里一行字"。

### G7 · 配色与字体无体系（`MainWindow.cpp:2672,2690,2701`）
3 处内联色值与系统默认调色板混用；无字号层级（标题/正文/次要/等宽）、无间距栅格；深色模式未适配。

### G8 · 对话框家族（`FileTreeDialog.cpp:72`、证书对话框 `MainWindow.cpp:2385-2386`）
固定 600×500；证书/目录对话框按钮无主次层级（"清除该主机信任"与"关闭"同款）。

### G9 · 危险操作无视觉区隔
【删除】【取消上传】【清除该主机信任】与普通操作同款按钮，删除虽有二次确认但视觉上无预警色。

## 2. 视觉与交互目标

### 2.1 设计令牌（落地为 `Theme.h` 常量 + `theme.qss`）

| 类别 | 令牌 | 取值 |
|---|---|---|
| 色彩·主色 | `--primary` | `#2563EB`（hover `#1D4ED8`，pressed `#1E40AF`） |
| 色彩·语义 | success / warning / danger / info | `#16A34A` / `#D97706` / `#DC2626` / `#0284C7` |
| 色彩·中性 | 背景 / 卡片 / 边框 / 主文本 / 次文本 | `#F8FAFC` / `#FFFFFF` / `#E2E8F0` / `#0F172A` / `#64748B` |
| 深色（跟随系统） | 背景 / 卡片 / 边框 / 主文本 | `#0F172A` / `#1E293B` / `#334155` / `#E2E8F0` |
| 字号 | 标题 / 正文 / 次要 / 等宽 | 15pt / 13pt / 12pt / 12pt（等宽仅用于哈希与日志） |
| 间距栅格 | xs/s/m/l/xl | 4 / 8 / 12 / 16 / 24 px |
| 圆角 | 控件 / 卡片 | 6px / 10px |
| 行高 | 表格行 | 32px（触摸友好 ≥ 28px） |

### 2.2 按钮层级（三级 + 危险态）
- **Primary**（主操作）：上传、下载 → 实心主色，每屏最多 1–2 个
- **Secondary**（次级）：刷新、新建文件夹 → 描边/浅底
- **Ghost/Icon**（辅助）：健康检查、存储空间、证书…、清空日志 → 无边框 + 图标 + tooltip
- **Danger**：删除、取消上传 → 危险色，且**仅出现在确认流程或溢出菜单中**

### 2.3 响应式断点（关键：适配多屏幕尺寸）

| 断点 | 布局 |
|---|---|
| **≥1280px** | 左：文件列表（伸缩）│ 右：预览面板 320px 固定；顶部单行工具栏；日志默认折叠 |
| **768–1280px** | 预览改为**可折叠抽屉**（默认折叠，点击行内"预览"图标展开）；连接配置收进可折叠区 |
| **<768px** | 单栏：列表铺满；预览与日志走**底部标签页/抽屉**；工具栏溢出菜单（`⋮`）收纳次要动作 |

实现手段：`QSplitter` 允许 `setCollapsible(1, true)` + 最小宽度约束；工具栏次要动作放入 `QToolButton` + `QMenu`（`setPopupMode(InstantPopup)`）；表格列用 `ResizeMode`（名称列 `Stretch`，其余 `ResizeToContents`）。

### 2.4 交互目标
1. **结果就近反馈**：操作结果以行内徽标 + 顶部状态条呈现（替代只写日志）
2. **空态引导**：列表为空时显示"还没有文件 · 【上传文件】/【刷新】"按钮，而非空白
3. **拖拽上传**：文件列表支持拖入文件即上传到当前目录
4. **双击预览**：双击行展开预览（等价右键"预览"），Esc 关闭
5. **错误可恢复**：失败提示带【重试】；401 时提示"令牌无效，请检查访问令牌"并聚焦令牌框
6. **键盘可达**：`Ctrl+U` 上传、`Ctrl+D` 下载、`Ctrl+L` 聚焦地址、`F5` 刷新、`Ctrl+F` 过滤，Tab 顺序遵循视觉顺序
7. **危险操作**：删除二次确认（保留现状）+ 危险色按钮；"清除该主机信任"独立区块
8. **进度语义**：进度条旁标注阶段（扫描哈希 → 上传 → 合并），取消按钮随时可见但仅在有任务时启用

## 3. 必须保留 / 遵循的现有规范（硬约束）

1. **服务端契约零改动**：所有路由、字段、状态码（含 401/409/416/507）与请求头（`X-CV-*`、`Authorization: Bearer`）不变。
2. **安全交互不得弱化**：TOFU 首次确认（含 `box.exec()` 必须真实弹出）、指纹不匹配拒绝且无"继续"、令牌密码框、【证书…】查看/清除入口必须保持在主界面可达。
3. **功能完整性**：分块上传/断点续传、Range 并发下载、同名覆盖询问、右键菜单全部动作（新建文件/重命名/删除/下载/打开文件夹/上传到此目录/排序）一个都不能少。
4. **中文界面与术语一致**：云匣、访问令牌、证书指纹、秒传、分块上传。
5. **工程约束**：不引入第三方 UI 框架、不迁移 QML（成本与风险不可控）；不上采样位图图标，图标用 Qt 标准图标或内联 SVG；不修改 `server/` 与 `client/tests` 相关脚本。

## 4. 可执行修改方案（三阶段）

### P1 · 设计系统与外壳（低风险，先见效）
| 动作 | 文件 | 做法 |
|---|---|---|
| 新增设计令牌 | `client/src/Theme.h`（新） | 色彩/字号/间距/圆角常量 + `applyAppTheme()` 声明 |
| 新增样式表 | `client/resources/theme.qss`（新） | 控件级样式：按钮三级、输入框、表格、进度条、徽标、折叠面板；含深色变体 |
| 资源挂载 | `client/resources/app.qrc`（新）+ `client/CMakeLists.txt` | `qt_add_resources` 打包 QSS；启动时读取 |
| 加载样式 | `client/src/main.cpp` | 调 `applyAppTheme(app)`；应用名去掉"测试"二字 → "云匣 CloudVault" |
| 统一字体层级 | `MainWindow.cpp:334-354` | 标题/正文/次要/等宽四档，移除散落 `setFont` |

**验收**：编译 0 error/0 warning；界面启用新样式；现有功能点击一遍无回归。

### P2 · 组件重构与响应式（主体工作）
| 组件 | 文件与行 | 改法 |
|---|---|---|
| 连接栏 | `MainWindow.cpp:196-238` | 拆为 ① 地址 + 令牌 + 【连接】按钮（一行，可折叠为"连接设置"）② 主操作工具栏（上传/下载/新建）③ 溢出菜单 `⋮`（健康检查/存储空间/证书…/清空日志） |
| 状态行 | `MainWindow.cpp:241-268` | 进度条独占一行（含阶段文案 + 取消）；空间/结果/证书迁至状态条右侧，用徽标样式 |
| 文件列表 | `MainWindow.cpp:279-292` | 列改为 **名称 / 大小 / 修改时间 / 状态**；ID→隐藏列，Hash/秒传→详细信息面板与 tooltip；`QHeaderView` 列宽策略；启用排序指示器；支持拖拽上传（`setAcceptDrops(true)`） |
| 预览面板 | `MainWindow.cpp:314-370` | `setCollapsible(1,true)`；窄屏默认折叠；空态设计；"仍要预览"改为次级按钮 |
| 日志面板 | `MainWindow.cpp:162` | 改为可折叠面板（默认折叠），错误时自动展开；新增【导出日志】；清空按钮移入面板头 |
| 三态与徽标 | 新增 `client/src/StatusBadge.h/.cpp`（或 Theme 内联） | 统一 成功/失败/进行中 徽标组件，替代 `setStyleSheet` 内联 |

**验收**：720×520 窗口下无横向滚动、所有主操作可达；1280×800 三栏正常；150% DPI 下无错位。

### P3 · 状态完善与可达性
空/加载/错误三态组件化；快捷键与焦点顺序；401 错误引导；进度阶段文案；日志导出。
**验收**：断网/401/同名冲突/磁盘满 四种异常路径均有明确界面反馈与下一步动作。

## 5. 验收标准（可量化）

1. 窗口 720×520 → 无横向滚动条，主操作（上传/下载/刷新）100% 可达
2. 窗口 1920×1080 → 列表与预览比例合理，列表名称列自适应填充
3. 表格列宽随窗口缩放，无硬编码像素；行高 ≥ 28px
4. 文案对比度 ≥ 4.5:1（AA 级）；危险操作有危险色
5. 全流程键盘可完成：选文件→上传→查看进度→取消→重试
6. 现有功能回归清单（右键 7 项、分块/断点、TOFU、令牌、同名覆盖）全部可用

---

## 6. 风险与"不做"清单

- **不做**：换 UI 框架、迁移 QML、重写网络层、改服务端契约、改 `src/`（旧原型，待其与 `client/` 关系判定后单独处理）。
- **风险**：`MainWindow.cpp` 2969 行单体，P2 阶段若同时改 UI 与网络易引入回归 → 采用"先拆组件、后调样式"的顺序，每步编译 + 关键路径手测。
- **建议顺序**：P1 → 编译验证 → P2（每拆一个组件即验证）→ P3。
